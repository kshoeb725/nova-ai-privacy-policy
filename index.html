Lawful Grounds for Processing Personal Data

Under Sections 4 and 6 of the DPDP Act 2023, personal data is processed strictly under the following lawful bases:

  • Explicit Affirmative Consent (Section 6): Optional Cloud AI processing (Allow Cloud Processing) across Google Gemini, NVIDIA API Catalog, OpenAI, DeepSeek, or OpenRouter is disabled by default and activates only upon explicit affirmative consent in Settings.
  • User-Directed Execution: On-device Qwen3 inference, local device tools (alarms, reminders, flashlight, volume, brightness, Do Not Disturb, app launching, calls, WhatsApp compose intents, calculator, local media), interactive wallpapers, and swipe-dismissible response popups with response-ID tracking execute solely on your direct prompts, gestures, or toggles.
  • Consent Withdrawal Scope: Withdrawing Cloud AI consent or switching to Offline AI mode immediately halts outbound Cloud AI requests and disconnects active client-side HTTP sockets. However, withdrawing Cloud AI consent does not disable separate user-initiated AI safety reporting (triggered only when you tap Report Issue and Confirm & Send) or override OS SpeechRecognizer / TextToSpeech services.

On-Device Processing & System Permissions Scope

Core device interactions, Qwen3 local inference, word-level lip-sync rendering, and personal memory storage execute on your Android device. Standard install-time permissions (such as VIBRATE, SET_WALLPAPER, or RECEIVE_BOOT_COMPLETED) run strictly locally without accessing personal records.

  • On-Device Qwen3 Language Models (Offline AI & Hybrid Local Routing): When you explicitly download an on-device model in AI & Offline Mode (Qwen3 0.6B Mobile ~378 MB or Qwen3 1.7B Balanced ~1.03 GB, Apache 2.0 GGUF executed via Llamatik / llama.cpp), the file is downloaded over HTTPS from Hugging Face and verified locally using a pinned SHA-256 checksum. Installed Offline Qwen3 inference runs 100% on-device with zero outbound prompt transmission.
  • Voice Recognition (Hindi/Hinglish) & Word-Level Lip-Sync: Spoken replies synthesize locally via Android TextToSpeech with natural timing and real-time word-boundary / phoneme lip-sync on Nova and Luma. Voice commands (English, Hindi, Hinglish) listen only on triple-tap, mic tap, or the optional brief follow-up listening window via Android SpeechRecognizer (which may route through your OS speech provider such as Google Speech Services depending on offline language packs).
  • Personal Memories & Non-Destructive Legacy Migration: Remembered facts, preferences, identity notes, and goals reside in local Room SQLite (wallpaper_agent_memory.db). New and updated memory values are encrypted field-level at rest via AES-256 GCM in Android Keystore (WallpaperAgentMemoryKey_v1) with no plaintext fallback. Historical plaintext or unprefixed records from prior app versions migrate non-destructively on access; if Android Keystore is locked/unavailable or a legacy row has not yet been accessed, existing records remain preserved untouched rather than deleted, so legacy migration may be pending until completed. Structural SQLite metadata columns rely on Android UID sandboxing without SQLCipher encryption.
  • Transient Session Memory & SAF Folders: Up to 20 recent dialogue turns remain transiently in RAM during active sessions. Local document search uses Android Storage Access Framework (SAF) limited solely to folders you authorize.

Optional Cloud AI Providers (Google Gemini, NVIDIA, OpenAI, DeepSeek & OpenRouter)

When you explicitly turn on Allow Cloud Processing in AI & Offline Mode (available in Hybrid AI or Cloud AI mode), queries travel over encrypted HTTPS to your selected Cloud AI provider: Google Gemini, NVIDIA API Catalog, OpenAI, DeepSeek, or OpenRouter.

  • Data Sent to Selected Provider: Your prompt, active volatile context (up to 20 turns), relevant Keystore-protected memory summaries (when memory personalization is active), and active companion instructions (Nova or Luma).
  • Explain Screen Vision Requests: Only upon explicit tap and system MediaProjection consent, one volatile frame (max 1024px JPEG) is transmitted to your active Cloud AI vision provider (such as Google Gemini Vision).
  • Model Discovery & Verification: Tapping "Discover Models" or "Verify" uses your Keystore-stored key over HTTPS to query that provider's model listing or health endpoint.
  • Provider Terms & Tiers: Logging, retention, and training policies depend on your selected provider and account tier (e.g., Gemini Free Tier vs. Google Cloud billing, NVIDIA, OpenAI, DeepSeek, or OpenRouter). Avoid sending sensitive personal information.
  • Client-Side Connection Cancellation: Toggling off Cloud AI, switching to Offline AI, or cancelling closes the local HTTP socket immediately, stopping further uploads, though it cannot guarantee server-side cancellation of packets already delivered to the provider's servers.
  • Cross-Border Transfer (Section 16 DPDP Act): Processed in global infrastructure operated by your chosen provider under applicable cross-border transfer frameworks.

AI Safety Reporting, Local Room Queue & Third-Party Processors

Nova provides a voluntary AI safety reporting workflow enabling you to flag harmful, offensive, abusive, or misleading AI outputs:

  • Voluntary, User-Initiated Submissions: No report is ever dispatched automatically. Transmission occurs only when you tap Flag / "Report Issue", review the preview, and tap "Confirm & Send".
  • Opt-In Excerpt (Excluded by Default): AI response excerpts are excluded by default (sent as an empty string) unless you check the opt-in toggle. Original user prompts and full chat logs are never included.
  • Disclosed Report Metadata: Includes issue category, companion persona (Nova or Luma), app version (2.0.1), deterministic client-generated reportId and idempotencyKey, optional sanitized notes/excerpt, and AI source metadata (providerName, modelId, executionMode).
  • Client-Side Privacy Sanitization & Local Queue: Client-side sanitizers strip email addresses, phone numbers, IP addresses, API/cryptographic keys, and local filesystem or content URI paths (/storage/emulated/..., /data/user/..., content://..., file://...); excerpts with excessive sensitive entities or private keys are dropped entirely. Local report queue and retry state persist in ai_response_reports.db (Room v2, non-destructively upgraded from v1) and are excluded from cloud backups.
  • Serverless Relay (Supabase Edge Function) & Resend Email Delivery: Verified reports route over HTTPS to submit-ai-report in Supabase and dispatch via Resend to shoebbussiness786@gmail.com.
  • Two Ephemeral Coordination Tables: Supabase stores no persistent report text, comments, or user profiles. It maintains only two ephemeral coordination tables: (1) an ephemeral rate-limiting table holding salted SHA-256 hashes of client identifiers with an automatic 10-minute expiration, and (2) an ephemeral idempotency table storing SHA-256 submission hashes, delivery status, and opaque email acceptance IDs for up to 24 hours to prevent duplicate emails during retries. Hashed identifiers are pseudonymous; automatic table expiration is distinct from instantaneous erasure of underlying cloud infrastructure access logs.
  • Optional Google Play Integrity Verification: On supported builds and devices, an optional Google Play Integrity Standard API token bound to a canonical SHA-256 hash of the report payload (protecting text privacy) may be attached. Submissions still succeed gracefully if Play Integrity is unavailable; server-side enforcement is configurable and defaults to disabled (ENFORCE_PLAY_INTEGRITY="false") unless explicitly configured and deployed live.
  • Third-Party Processors & Inbox Retention: Delivered report emails remain in the developer inbox for safety triage until manually deleted or archived. Supabase Inc. and Resend Inc. process relay and transactional email metadata under their privacy policies.

Security Safeguards, Cryptography & Backup Exclusions

Pursuant to Section 8(5) of the DPDP Act 2023 and Android security best practices, Nova implements layered safeguards:

  • Network Transport Security: All outbound traffic (Cloud AI providers, SHA-256 verified Qwen3 downloads, and Supabase reporting) enforces encrypted HTTPS (TLS 1.2 / 1.3), with cleartext HTTP blocked by Android platform security policies.
  • Android Keystore Field-Level Encryption (No Plaintext or Software Fallback): API keys for all five Cloud AI providers (NovaGeminiApiKey_v1) and new/migrated personal memory values in Room (WallpaperAgentMemoryKey_v1) are encrypted at rest with AES-256 GCM in AndroidKeyStore (hardware TEE/StrongBox on supported devices). Production builds enforce fail-closed writes with no plaintext fallback and no persistent software-key fallback; if Keystore is locked or unavailable, new sensitive writes are refused without saving plaintext while existing unmigrated rows stay preserved until migration succeeds.
  • Application Sandboxing: Local Room SQLite files (wallpaper_agent_memory.db, ai_response_reports.db) sit in app-private storage protected by Android Linux UID isolation (0600). Structural metadata columns do not use file-level SQLCipher encryption.
  • Backup & Device Transfer Exclusions: Both backup_rules.xml and data_extraction_rules.xml exclude wallpaper_agent_memory.db (plus -wal, -shm, -journal), ai_response_reports.db (plus -wal, -shm, -journal), Keystore credential/fallback prefs (wallpaper_agent_privacy_prefs.xml, wallpaper_agent_keystore_fallback.xml), SAF tokens (agent_file_access_prefs.xml), and reporting/wallpaper prefs (nova_report_config_prefs.xml, wallpaper_dest_prefs.xml) from Google Drive backups and device transfers.

Data Retention, Erasure & Uninstall Clarification

Under Section 12 of the DPDP Act 2023 and Google Play policies, you control your local records:

However, uninstallation does not automatically remove prior safety report emails delivered to the developer's inbox or standard server access logs held by third-party processors (selected Cloud AI provider, Supabase, Resend, or Hugging Face).
